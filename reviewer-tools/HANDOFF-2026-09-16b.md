## How the review loop actually runs

So the next session does the same thing rather than inventing it:

1. Poll the open PR heads every ~3 minutes; re-review unprompted when a head
   moves. Never ask Sid to ping you.
2. Review at max depth. Run lint, typecheck and the full suite at the exact head.
   Single test file: `npx.cmd vitest --config vitest.workspace.ts run <file>`
   (`npm.cmd run npx` does not exist and fails silently — it is in old scripts).
3. For any guard that matters, mutate it and require a **named** test to fail,
   with **BASE surviving**. Serialize mutation runs; a concurrent checkout in
   another worktree invalidated one this session.
4. Write the verdict as a file, prepend it to `docs/AGENT_LOG.md` (newest first,
   CRLF, never edit another session's entry), commit and push to `main` without
   asking. If the log has diverged, union-merge with
   `tools/agentlog-union.mjs … crlf`.
5. Merge what you clear, at the exact reviewed head, then verify `main` is green.
6. After every merge, queue the builders' next task unprompted.
