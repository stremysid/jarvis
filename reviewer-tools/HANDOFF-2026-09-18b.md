## 3. The finding that matters most

**Automatic memory has never produced a recallable fact.** Verified in
production, not inferred: 36 distillation runs, 251 events, **5 items created,
0 active, 5 proposed**.

Every model-extracted fact is stamped `origin=model`, `basis=inferred`,
`proposed`. All four read paths exclude exactly that triple, and
`MemoryOwnerControls.confirm()` **refuses the same triple** — while the receipt
it writes says "Saved 1 uncertain model-inferred memory **for confirmation**".
A closed loop with no exit: not recallable automatically, not promotable
manually.

The fix (brief in `relay/memory-recallable-prompt.txt`) does two things: let
confirm honour its own receipt, and make proposed+uncertain items recallable
*with their uncertainty label* rather than unreachable. `active` becomes a
ranking tier, not a gate.

## 5. Why that method changed

A read-only auditor found **three real defects in code I had already cleared**,
one of them live in production:

1. **A-4** — `assessAuthenticity` took the *last* `Authentication-Results`
   group; mail hops *prepend*, so it read the sender-controlled one. In code I
   cleared 40 minutes earlier. Fixed in #95.
2. **B-1** — voice had no suppression anti-join, so a fact Sid forgot came back
   on the next call. Live. Fixed in #93.
3. **B-2** — a 4-digit PIN matched no redaction rule, so a spoken PIN was stored
   verbatim. Fix is in #96, which is otherwise sent back.

Mutation testing proves a guard *fires*. It cannot prove the guard reads the
*right input*, and it cannot find a path no test exercises. Both gaps need a
second reader with no stake in the spec. **Keep the auditor pass before clearing
anything security-relevant.**
