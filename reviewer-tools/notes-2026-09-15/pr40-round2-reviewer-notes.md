# PR #40 round 2 (337c290) — reviewer's own reading notes

- B1 SQL: all 9 tables `STRICT, WITHOUT ROWID`; every insert guard gains an existing-key EXISTS; the new `owner_call_step_up_alerts_insert_guard` and `_key_guard` are added. Update guards: bindings, windows, successes, reprompts, rejections and guest_pin_attempts are fully immutable. Attempts (232–238) and repeat_checks (458–462) pin every PK column. Alerts pin the PK (517–520).
- bind(): read-then-insert, and a conflict throws on a JSON mismatch. createdAt comes from `session.createdAt` (inbound.ts:408, outbound.ts:457), which is stable across Twilio retries, so an exact retry stays idempotent. JSON.stringify key order comes from the same snapshot builder (`binding()` mapper vs input literal): check that both use the same key order, or a legitimate retry fails closed.
- Alert sink: INSERT…SELECT WHERE NOT EXISTS, then UPDATE. D1 serializes statements, so there's no race to the insert guard.
- B2: alarm() now deletes the key after the socket loop (call-session-do.ts ~1699–1704). With zero sockets it still deletes without handling. That's pre-existing, and a call with no media socket is over anyway.
- B3: the SQL authority trigger requires an active head plus an active verifier matching principal and identity. The DO calls `assertWaiverAvailable` before `#mintWaivedOwner`. The repository has two waiver checks (1381, 1577).
- S1: `#guardOwnerRepeat` holds 1–2-word fragments made only of passphrase-list words while the repeat status is `available`. That status holds until a 3-word list candidate spends the one repeat check, which can be the whole call. A held fragment is dropped, never returned, if the next utterance doesn't combine or the 2 s assembly window lapses (347–350, 369–377).
  - Word list contains common replies "good" and "next" (owner-passphrase-word-list.ts 859, 1170). So an owner saying just "good" or "next" after verification can be swallowed, including inside the owner-access confirmation flow.
  - LOW (UX/functional), not security. Suggest: flush held non-phrase fragments back to the prompt path when assembly fails or times out, or bound the `available` period (e.g., the design's repeat window).
