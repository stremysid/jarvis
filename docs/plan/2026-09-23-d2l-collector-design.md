# D2L collector: final receiving design

Approved by Sid on 2026-09-23. School is the priority. The separate Opera GX extension uses the existing session on the PC and laptop to GET Valence JSON from `ldsb.elearningontario.ca` (LP 1.43, LE 1.82). No password, cookie export, DOM reader, school write, or ordinary Jarvis device credential is involved. The [P2 login-and-scrape brief](../briefs-p2-d2l-read.md) is parked.

**Authority.** Migration **0040_school_collector_keys.sql** creates a separate Ed25519 registry, pending/active/revoked state, device label, pairing timestamps, and separate nonces. Database guards prevent registering the same key in `device_keys` in either direction. The existing ordinary verifier still reads only `device_keys`. Collector signatures cannot authorize `/sync/pull`, `/sync/ack`, `/memory/distill`, or `/sync/memory/project`, even with their correct audience. Only pure parsing/signature helpers are shared.

**Pairing.** `POST /school/pairing/start` takes canonical `{publicKeyBase64,deviceLabel}` and returns `{collectorId,principalId,challenge,code,expiresAt}`. The owner comes from deployment configuration. Four starts per ten minutes bound the public entry. The extension displays the eight-character code and signs `POST /school/pairing/prove` with `{challenge}`. Possession consumes that challenge once and raises a ten-minute decision through the existing owner decision queue and Telegram keyboard. Delivery is recorded only after the provider succeeds. A matching authenticated owner Confirm tap activates exactly that immutable key; rejection, a foreign decision, replay or expiry cannot. Signed `POST /school/pairing/status` with `{}` returns only that key's state. The `school_collector_revoke` owner tool uses the existing tier-3 gate. Revocation is terminal; replacement requires a new pairing.

**Wire contract.** Signed routes use `x-jarvis-signed-request`, SignedRequestV1, audience `jarvis-school-collector`, a 32-byte random nonce, canonical JSON body hash, and a five-minute signature window. The envelope's `deviceId` is the collector ID. `POST /school/observations` accepts **one course per batch, at most 65,536 bytes**:

```text
{schemaVersion:"1.0", host, readId, startedAt,
 courseIds:[all courses attempted], enrollmentComplete:boolean,
 course:{id,name}, routes:[{route,status,fetchedAt,complete,body}]}
```

IDs are bounded letters/digits/underscore/hyphen; timestamps are RFC 3339 UTC with milliseconds. Reuse the read ID and immutable complete course manifest across a read, including failed courses. `status:0` records transport failure. Mark unfinished paging `complete:false`; never omit a failed course. Supported relative LE 1.82 routes are folders, content/toc, optional content/myItems/, grades/values/myGradeValues/, and per-folder submissions/ or submissions/mysubmissions/. A course requires folders, toc, grades and a submission result for each folder. Limits are 128 courses and 256 route results per batch; an oversized course cannot be silently truncated. A new nonce retry of identical bytes returns the same batch receipt. Changed bytes or manifests conflict.

**Evidence and deadlines.** Store route, course, HTTP status, fetched time, completeness, observed shape and raw JSON before projection. Preserve undated items in the batch's mapped JSON and raw evidence. Use linked ToolItemId dates in this order: content/myItems, assignment DueDate, topic/module EndDateTime labelled **availability end**. Every projected title and mapped item labels its date source. `DeadlineIngestion` retains its revision, validation and disappearance safeguards. A dated item is not erased when it disappears. Delayed device evidence is retained without rewinding newer deadlines. Any failed course fails the whole read; unfinished courses keep it incomplete. Ingestion failure also prevents a good-read claim.

**Honesty and access.** `school_d2l_status` is available to the owner agent on Telegram and voice: last good whole read, latest state, refusals, collectors and cursor-paged evidence. Its freshness threshold is supplied by Jarvis; the deterministic digest uses the existing twelve-hour school convention and reports failed, incomplete, stale, never-read or unavailable states as protected gaps. It cannot print “nothing due” for those states. Empty confirmed-200 submissions and absent grades remain evidence. Folder counts of -1 mean no usable submission count. Only a positive own-submission status is labelled submitted. No code labels work missed. Source content is untrusted; a signature proves the collector said it, not D2L authorship.

**Verified premises and limits.** [#161](https://github.com/stremysid/jarvis/pull/161) provides observed folder/toc shapes, null DueDate, denied counts, 200-empty grades and `/submissions/`, and 403 whoami. It does **not** observe `/mysubmissions/`, populated grades/submissions, or content/myItems. The narrow myItems array adapter (`ToolItemId`, `DueDate`) and positive Status fixture are explicitly synthetic and need probe confirmation; unfamiliar shapes fail the read. [#160](https://github.com/stremysid/jarvis/pull/160) supplies key isolation and pairing rationale. Both reports were open at inspection, not merged. Public pairing can be rate-limit exhausted; a failed notification leaves a queued decision, not an activated key. Zero-course enrollment cannot establish an empty-school claim with this per-course protocol. Live extension transport, school coverage and delivery remain owner acceptance work in [OWNER-ACTIONS](../OWNER-ACTIONS.md).
