# D2L collector: final receiving design

Approved by Sid, 2026-09-23; compatibility update 2026-09-24. The Opera GX collector on PC and laptop uses the existing session to **GET Valence JSON** from `ldsb.elearningontario.ca` and `durham.elearningontario.ca`, LP 1.43 / LE 1.82. Sid's online CIA4U1 course is on Durham. No password, cookie export, DOM reader or school write. The [P2 login-and-scrape reader](../briefs-p2-d2l-read.md) is **parked**.

**Separate authority.** Migration `0040` creates Ed25519 collector keys (label, pending/active/revoked, timestamps), their nonces, reads, batches and immutable evidence. Reciprocal guards prevent reuse in `device_keys`. Collectors cannot call `/sync/pull`, `/sync/ack`, `/memory/distill` or `/sync/memory/project`. Migration `0045_school_collector_hosts.sql` adds host provenance, unknown-projection labels and unique pairing decisions. It moves legacy LDSB sources to `d2l-api:ldsb.elearningontario.ca:<course>` while preserving deadline IDs, revisions, status and reminders. New sources use `d2l-api:<host>:<course>`; the retired source row stays inactive history. Old reads default to LDSB because that was the only accepted host.

**Pair and revoke.** Canonical `POST /school/pairing/start` takes `{publicKeyBase64,deviceLabel}` and returns `{collectorId,principalId,challenge,code,expiresAt}`. Four starts per configured principal per ten minutes bound this public entry. The extension displays its code and signs `/school/pairing/prove` with `{challenge}`. Fresh-nonce retries reuse one durable decision, including after decision creation or Telegram notification fails. Delivery is recorded afterwards; ordinary successful retries do not resend it. Only Sid's matching, unexpired Telegram Confirm tap activates the key. Signed `/school/pairing/status` with `{}` returns key status. **Reading evidence spends no action tap.** Revocation validates arguments before consuming one tier-3 tap and is terminal.

**Unchanged signed course wire.** `x-jarvis-signed-request`, SignedRequestV1 canonical body/hash/path, audience `jarvis-school-collector`, random 32-byte nonce and five-minute signature window remain. Its `deviceId` is the collector ID. `POST /school/observations` accepts one course under **65,536 bytes**:

```text
{schemaVersion:"1.0", host, readId, startedAt,
 courseIds:[all courses attempted], enrollmentComplete:boolean,
 course:{id,name}, routes:[{route,status,fetchedAt,complete,body}]}
```

The immutable manifest accompanies every course, including failures. UTC timestamps carry milliseconds. Limits remain 128 courses, 256 routes, 32 container levels and 4,096 structural items. Identical-byte retries need a new nonce and retain the receipt. Folders, toc, grades and each folder's submissions result are required; complete refusals count as observed results. Course routes now include `news/` and `quizzes/`. Global `content/myItems/?orgUnitIdsCSV=<course>` accepts the observed `{Objects:[],Next:null}` and legacy arrays. Query-bearing page routes are accepted; each Next link must have its matching observed page. The receiver never fetches links.

**Additive host-failure form.** Keep those same fields, set `course:null`, `courseIds:[]`, `enrollmentComplete:false`, and include at least one versions or enrollment result. Example: `/d2l/api/versions/`, status 0, complete false, body `{collectorFailure:"session-expired"}`. An oversized manifest uses `/d2l/api/lp/1.43/enrollments/myenrollments/`, its actual status, complete false, and `{collectorFailure:"course-manifest-too-large",courseCount:N}`. Use a distinct read ID per host, as #170 already does. These batches always record failed host reads without inventing courses. No path, schema version, signature field, header or existing course-batch field changes.

**Evidence before projection.** Persist actual host, route, course (null for host failure), status, fetched time, completeness, shape and raw JSON. Unknown JSON stays labelled in `unmapped_json`; it does not fail receipt or block unrelated projections. Assignment date priority remains **content/myItems → assignment DueDate → topic/module EndDateTime**, the last labelled **availability end**. Quizzes use documented `QuizId`, `Name`, `DueDate` and `EndDate`: distinct due/end dates retain separate projections labelled **quiz DueDate** / **availability end**. Undated work remains. Announcements stay raw; publication/expiry is not an assignment deadline. Empty student `200 []` means **unknown**. Existing ingestion safeguards stay. Complete **403/404** tools are normal refusals/missing tools. Status 0, 401, 5xx and incomplete paging fail the read; redirects and non-JSON bodies mean **session expired**. One failed course fails its host read; success on another board cannot mask it.

**Jarvis judges.** `school_d2l_status` adds per-host health, host provenance, unknown-projection counts and refusal dispositions. Latest/last-good queries each return at most one row per observed host. Refusals are bounded across those latest reads; paged evidence retains history. Combined last-good time is the oldest host time, or null if a reported host has never succeeded. Jarvis chooses freshness; the digest's existing twelve-hour default remains. Failed/stale/incomplete reads, unknown projections and undated work prevent “nothing due”; host gaps name the board and expired session. Empty submissions, absent grades and denied `-1` counts do not decide missed work. Only a positive own-submission status can mean submitted. Jarvis interprets the evidence.

**Limits and rollout.** See [retention/public-pairing gaps](../../KNOWN_ISSUES.md#school-collector-retention-and-public-pairing-remain-bounded-only-in-part) and [compatibility evidence](../reviews/2026-09-24-d2l-receiver-fix.md). A collector signature is not a D2L attestation. Status covers hosts that have reported; zero-course success and unseen boards are not proven empty. Owner acceptance/deployment remain in [OWNER-ACTIONS](../OWNER-ACTIONS.md). No real database, migration or deployment was touched.
